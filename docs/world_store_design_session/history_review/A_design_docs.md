## Contradictions and tensions between the new top and earlier decisions

1. **Separating today's data from earlier days (Goal 2) vs removing day/time from the store.** The top wants data from the current day or deployment shown distinctly from earlier days. The earlier design dropped per-day epochs (ADR-0002 A1 superseded by #221; register R5 "one fused grid per layer") and dropped per-cell time and source (ADR-0002 A2.2; register R8 "source/time stay out"). The only time the old text keeps is a per-Item (per-tile) observation interval (rev 3 Part 2 line 2). So the top's display need can only be met at tile granularity unless something is reinstated. The top does not say which.
2. **"Live tiles are replaced by rebuilt tiles" vs cell-wise clearing.** ADR-0010 D8 clears live (draft) cells only where the rebuild has data; live cells in the rebuild's gaps survive. The top says live tiles are replaced "when practical" and leaves "how a machine knows the full data has arrived" open. Not a clash yet, but the cell-wise rule is not carried.
3. **Cleaning.** Top Not-goal "Data cleaning as a workflow" narrows register R7 ("add a data-cleaning layer") and prior art Part 2 ("single biggest human-facing gap ... should be named"). The top keeps recorded marks, so it is a narrowing, with the open question still pointing at manual cleaning for target search and archaeology.
4. **Every tile says what it was built from (top) vs 2026-10-01 direction.** The direction note says a per-tile fingerprint and per-tile STAC Item wait, with "one build record per site" as the stand-in. The top asks for a per-tile built-from label and a build record of unstated size (open question). Compatible only if the label is a small field and not the fingerprint.
5. **"Nothing should assume navigation from RTK GPS" (opening) vs earlier decisions.** ADR-0002 D4 and ADR-0010 D5 make the whole vertical world GNSS ellipsoidal (map_tide self-measured from GNSS, datum converted at import), and rev 3 section 4 fixes one ITRF2020 frame. This works for any GNSS but not for an underwater vehicle without it. The top says the design should not preclude that; the earlier decisions do lean on GNSS vertical.
6. **Export wording.** Top Goal 4 frames export as GSF/XTF of the recording. Rev 3 and the HSSD review frame publish as BAG/S-102 from reviewed products. Not a contradiction (the Not-goal leaves publishing to the traditional chain) but the two exports are different things and the older "publish" is now unplaced.
