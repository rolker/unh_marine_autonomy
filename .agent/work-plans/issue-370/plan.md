# Plan: export a whole-area GeoTIFF from a tiled raster layer (Slice A)

## Issue

https://github.com/rolker/unh_marine_autonomy/issues/370

## Context

No tool turns a layer's per-GGGS-tile GeoTIFFs into one mosaicked GeoTIFF. The
immediate driver is a Kongsberg M3 backscatter GeoTIFF of the Appledore /
Isles of Shoals survey at native level 10 (host store
`~/data/world/imagery/backscatter/survey`, Float32 x3 bands, no `overviews/`).
Depth (`depths/processed`, Float64 x2) has an `overviews/` sidecar (levels 0-9
plus `coverage.json`). Scope is Slice A of the Issue Review (operator-confirmed):
box-required CLI, depth and MBES backscatter, native or sidecar level. Deferred
items are in Follow-ups.

## Approach

**Placement: `marine_tiled_raster_store`.** It is the only package both stores
already depend on (it owns `TiledRasterTile<T>`, tile I/O, `gridsInDir`,
`scanCoverage`, `loadCoverageManifest`, and already links GDAL + nlohmann_json),
so the exporter reads depth and backscatter tiles with no
`marine_bathymetry_store` dependency and no new package. It reads
`<layer_dir>/../registry.json` generically (one JSON key, `datum`, the SOURCE datum of the import) rather than
linking either store's registry class.

1. **Library `export_geotiff.{hpp,cpp}`** (testable core, CLI is thin):
   - `ExportOptions {box (latmin,lonmin,latmax,lonmax), level optional, max_pixels}`; `max_pixels` has **no in-library default** (the CLI supplies the documented default; unit = pixels per band, i.e. width*height, independent of band count). `ExportResult {width,height,nodata_count,source_level,source_kind,geometric_error_m,band_names,vertical_datum,source_vertical_datum,warnings}`.
   - **Dtype probe is required.** A small GDAL header read (`GDALOpen` + `GetRasterDataType`/band count, no pixel I/O) in the new .cpp checks every tile in the selection before any output is created. Only Float32 and Float64 are accepted; any other dtype (e.g. uint16 sidescan) is refused with a message naming the tile and dtype. Mixed band counts across selected tiles are refused, and so is a band declaring a no-data value other than NaN (pixels are read raw, so a finite sentinel such as `-9999` would be exported as data under the NaN no-data tag; every current float writer uses NaN). The probe also checks each tile's pixel grid against its named grid (960 x 960 pixels, pixel size equal to the level's cell span in both axes, no rotation terms, origin on the grid's north-west corner to within 1e-6 cell, floored at 1e-12 deg) and fails the export on a mismatch: `loadTile` recovers a tile's grid from its origin only and accepts an origin up to half a cell off, so a tile with another pixel size would otherwise be stretched into place, and one with an off-grid origin shifted by a fraction of a cell. An unreadable, mis-sized or non-WGS84 tile (`loadTile` throws) fails the whole export loudly; no partial file is left. Every GDAL failure message carries GDAL's own reason (`CPLErrorReset()` before each checked call, and tile_io's step-only errors from the strip loop get the reason appended).
   - Every tile is read as double (`loadTile<double>`; GDAL converts Float32 exactly) and cast once to float on write, so output is always Float32. NaN maps to NaN. Metadata `DOWNCAST=Float64->Float32` is recorded when any source band is Float64 (it applies to all bands, the uncertainty band included); a selection whose bands are all Float32 already (backscatter) records `DOWNCAST=NONE`, since nothing was cast. A finite value outside the Float32 range (written as +/-inf) is counted and warned about. Rationale: float32 spacing is about 7.6e-6 m for |values| of 64-128 m (micrometre-level; about 1e-3 m only near 8 km), against cm-dm sounding uncertainty and a 0.9 m nominal cell.
   - Band names come from the band-count table only: 2 bands = `depth,uncertainty`; 3 bands = `mean,scaled_standard_error,sample_sd`; any other count = `band_N`. The dtype check above is what keeps this table from mislabelling a non-float layer. No `--layer-kind` and no `--band-names` option; no layer directory name is inspected. The datum gate (item 6) follows the band-count/registry rule stated there, not a user-supplied kind. Any other band count is exported with `VERTICAL_DATUM=UNSPECIFIED`, no `SOURCE_VERTICAL_DATUM`, and a WARNING that it matches no known layer kind.
2. **Tile selection (ADR-0011).** Level = `--level` or the finest native level that intersects the BOX (judged from the tiles inside the box via `gridsInDir` / `scanCoverage`, not whole-layer). With no `--level` and no native tile in the box, refuse (item 3) and name the sidecar levels that do intersect it, so the operator can pass `--level`. Per-tile precedence at the requested level: native `(level,row,col)` first, else sidecar `overviews/<level>_<row>_<col>.tif` (flat sidecar, ADR-0011), else hole (NaN). Native always wins, derived is never merged into native. If the requested level is finer than the finest native level in the box and no native tile exists at it, refuse (no upsample). If a level is coarser, has no native tile in the box and is absent from the sidecar (or no sidecar), refuse with a message naming the available levels and pointing at the overview builder. No on-the-fly folding. A box where the requested level has some native tiles and some sidecar tiles is valid. `SOURCE_KIND` is `native`, `overview` or `mixed`. When native tiles at OTHER levels exist inside the box and their data is, or may be, missing from the export, emit a WARNING listing those levels. Three cases, the first two judged per tile position from names alone: (a) a native tile at another level covers an export-level position with no tile (native or sidecar), which becomes a NaN hole (every uncovered position beneath a coarser native tile; a finer native tile's own export-level ancestor position when the sidecar lacks it); (b) a finer native tile has a NATIVE ancestor at a level from the export level up to its own (exclusive), so the fold (ADR-0011 fold scope: derived tiles are never written over native ones) never carried its data to the export level; (c) a coarser native tile lies under export-level tiles (native or sidecar) that are NaN in band 1 somewhere inside the window, judged by the writer as it clips each such tile: neither kind of export-level tile carries coarser data (a sidecar tile is folded only from finer levels), so a coarser level is replaced where an export-level tile exists, never used to fill its holes, and its data there may be lost. A native tile at another level whose export-level position lies outside the export's tile range (possible because the snap tolerance is per level, so a box edge just past a tile boundary can take in a finer tile at its own level) is never counted, in either name-based case. That warning is worded separately ("NOT used to fill holes") and counts the band-1 NaN cells; the coarser tile is not read, so it says "may". No warning where a sidecar tile carries the finer native data with no native tile in between (an explicit coarse `--level` over an up-to-date pyramid), or where a coarser native tile lies under export-level tiles that are fully valid in band 1 wherever the window crosses it. Geometric error: sidecar tiles use `geometricError` from `overviews/coverage.json` (report the max over contributing tiles); native tiles report the nominal equatorial `Level::cellSize()` (documented as nominal, not local ground size). A sidecar tile with no recorded error (no or unreadable `coverage.json`) falls back to the nominal cell size with a WARNING that this understates a derived tile's error. Tile-shaped names `gridsInDir` cannot parse are counted and warned about (one inside the box becomes a hole). The sidecar is trusted as found: a stale pyramid is not detected (#389), and exports assume a quiet store; the README says both. The one concurrent change caught is an overview rebuild swapping in a new `overviews/` (the builders publish by rename) while sidecar tiles are read: the directory's `(st_dev, st_ino)` is recorded before it is listed and compared before the rename, and a change fails the export (nothing written), since it could otherwise mix two sidecar generations.
3. **Empty selection.** A box that intersects no tiles at the chosen level exits non-zero with a clear message and writes no file.
4. **Georeferencing and strip writing.** The mosaic is defined in integer global GGGS cell indices: lattice origin -96 deg lat / -180 deg lon, tile origin = `row*960`, `col*960` cells; the lat cell span is constant per level and the lon cell span scales by the scale factor (1/3/9 at |lat| >= 72/80). The box is snapped outward to the level's cell grid in integer indices; window offsets are integer subtractions, never float geotransform division; the geotransform is derived once from the integer origin. A box reaching |lat| >= 72 deg (tile_io is validated only below 72) or crossing a scale-factor boundary is refused, since one north-up pixel width cannot span bands. Row orientation: files are north-up on disk and `loadTile` flips once into the in-memory GGGS order (row 0 = south); the exporter reconciles orientation in exactly one place, mapping output row `y` (0 = north) to global cell row `row_end - 1 - y`, whose tile row and south-first local row index the loaded tile. Pixel rows within a tile are not flipped again. This is called out in the code and covered by the placement test (every pixel, plus a geographic cross-check read straight from the north-up source files). A loaded tile whose georeferencing does not match its filename fails the export (it would otherwise be placed by name). Compute `width*height` in 64-bit arithmetic before the cap check; if it exceeds `--max-pixels` refuse before allocating anything (equal to the cap is accepted, cap+1 refused). A width or height above the GeoTIFF/GDAL `int` dimension limit is refused too (only reachable with a raised cap). Create the GTiff (`TILED=YES, COMPRESS=DEFLATE, PREDICTOR=3, BIGTIFF=IF_SAFER`), north-up EPSG:4326, and write one block-row strip at a time: load only the tiles overlapping the strip, fill NaN where no tile covers, `RasterIO` the strip once. Memory is bounded by the window, not by tile count: the strip is `min(height, 256)` rows, each tile is loaded once and only its cells inside the window are kept as Float32 (the decoded double tile is dropped at once), and the cache spans at most two tile rows, so peak memory is about `4 B x bands x width x (min(height, 1920) + min(height, 256))` (never more than twice the uncompressed output, which `--max-pixels` caps) plus a fixed part: one decoded tile (7.4 MB per band as double), `loadTile`'s 7.4 MB read buffer and GDAL's own state, measured at about 85 MB RSS in all for 2 bands. The peak is about twice the output only for a large output; for a small one the fixed part dominates (measured: a dense 12,449 x 3,810 2-band export, 379 MB uncompressed, 217 MB predicted by the formula, 299 MB peak RSS). No output block is read-modify-written. NoData tag = NaN. NoData count = total cells - non-NaN cells written (tiles never overlap at one level), per band, reported for band 0 in the summary and per band in the result.
5. **`--max-pixels`**: CLI option, default documented as 250,000,000 pixels per band (1 GB of Float32 per band uncompressed; multiply by band count for the total); the number lives only as the CLI default / one named constant referenced by the help text. It is never a compile-time wall: any value may be passed to raise or lower it.
6. **Datum policy.** Stored depth is always WGS84 ellipsoidal (ADR-0002 D4, `marine_bathymetry_store` `registry.hpp`); registry `datum` is the SOURCE datum the import converted FROM (empty = source was already ellipsoidal). Depth-like layers (2-band Float, band-count rule of item 1) therefore get output `VERTICAL_DATUM=WGS84_ELLIPSOIDAL` regardless of the registry, and `SOURCE_VERTICAL_DATUM=<registry datum>` (`UNKNOWN` if empty, missing or unparsable). Empty/missing/unparsable registry: print a loud multi-line WARNING to stderr worded "source datum conversion not recorded" (never "datum unknown"), and continue (do not refuse). For an EMPTY `datum` the warning adds that the value is ambiguous rather than missing, since per `registry.hpp` empty also means the source was already ellipsoidal. The registry path is `<layer_dir>/../registry.json` after `weakly_canonical` (symlinks resolved, the same canonicalisation as the store guard) and stripping a trailing slash from `<layer_dir>` (so `a/b/` resolves to `a/registry.json`, and a symlinked layer path finds its own store's registry, not the link directory's); a missing or unparsable file takes the same warn path and never throws. The registry is shared by sibling layers (`processed`, `chart`, `reference`) and may describe a different layer (e.g. a chart-datum source); the README says so. Backscatter-like layers (3 bands) are exempt: no datum check, `VERTICAL_DATUM=NOT_APPLICABLE`, no `SOURCE_VERTICAL_DATUM`.
7. **Metadata tags** (dataset-level): `SOURCE_LEVEL`, `SOURCE_KIND=native|overview|mixed`, `GEOMETRIC_ERROR_M`, `BAND_NAMES`, `VERTICAL_DATUM`, `SOURCE_VERTICAL_DATUM` (depth only), `DOWNCAST`, `NODATA_COUNT`. Band descriptions set via `GDALSetDescription` on each band. The horizontal-CRS note, `SOURCE_LAYER_DIR` and `BOX` tags are out of approved scope and moved to Follow-ups.
8. **CLI `export_geotiff`** (`src/export_geotiff_main.cpp`): `<layer_dir> --box LATMIN LONMIN LATMAX LONMAX -o out.tif [--level N] [--max-pixels N]`. Box is required; validates min<max and lat/lon ranges. Numbers are parsed strictly: `--level` / `--max-pixels` accept decimal digits only (a sign, whitespace or any other character is a usage error, so `" -1"` can never wrap to UINT64_MAX and switch the cap off), and a `--box` value may not carry leading whitespace or trailing text. Prints a summary (tiles used, size, level, source kind, NoData count, warnings). Exit codes: 0 ok, 1 runtime failure/refusal, 2 usage. Output is written to a unique `out.tif.tmp.XXXXXX` in the same directory, created exclusively (`O_CREAT|O_EXCL`, mode 0666 under the umask), `GDALClose` return is checked, the file is `fsync`ed (a failure throws, removing it), then renamed over `-o`, and the directory is `fsync`ed after the rename (a failure there is a warning, since the output is already in place; EINVAL/ENOTSUP, a filesystem that cannot sync the object, count as success). (Implemented inside `exportGeoTiff()`, which takes the output path, so the tests cover it directly; the CLI stays a thin argument parser.) An output anywhere under a store directory of the layer is refused (the layer, its `overviews/`, any subdirectory, sibling layers, the registry itself; the store is read-only to this tool). A store directory is found by content, not position: the nearest directory above the layer holding a `registry.json` (searched from the layer's parent, so a stray `registry.json` inside a layer cannot pose as the store and leave the real store unguarded), plus the layer's parent, each looked up along both the path as given and its `weakly_canonical` form, so a symlinked layer guards the store holding the link as well as the one holding its target. A `<layer_dir>` named `overviews` (an `overviews/` sidecar, given as given or after resolution) is refused with a message to pass the layer directory, whose sidecar is read automatically. Paths are compared after `weakly_canonical`, so a symlinked layer or output path cannot get past it, and the check runs before any file is created. An existing `-o` is overwritten via the rename (atomic replace); after the rename, the previous output's GDAL sidecars (`<out>.aux.xml`, `<out>.aux`, `<out>.ovr`, `<out>.msk`, and their upper-case extensions) are removed, as GDAL's own overwrite would, so stale statistics, overviews or a mask never attach to the new raster (a sidecar that cannot be removed is a warning; nothing not derived from the output name is touched). Only this run's own temporary file is removed, on every failure path (throw, close error; a refusal happens before it exists), so a refused or failed run leaves neither a partial output nor a stray temporary file, an existing `-o` is untouched, and two exports aimed at one output cannot unlink or rename each other's file. An interrupted run cleans up too: the library records each in-flight temporary path in a fixed table of slots (lock-free atomics, blocking SIGINT/SIGTERM/SIGHUP between creating the file and recording it) and `removeInFlightExportTmpFiles()` unlinks them async-signal-safely; the CLI calls it from a SIGINT/SIGTERM/SIGHUP handler (`SA_RESETHAND`) and re-raises, so it dies of the signal with no `<out>.tmp.XXXXXX` left and the output untouched. The same three signals are blocked again from just before the rename through the stale-sidecar removal and the directory `fsync`; right after the rename the library bumps a lock-free counter, `exportOutputsReplaced()`, so a signal held back there (or arriving later) is reported by the CLI handler as "the output WAS replaced", never "nothing written", and never stops the run with the old sidecars still attached to the new raster. There is no stale-temporary-file cleanup: a crashed run's leftover is left for the operator, because removing a file this run did not create could delete another run's in-flight file or a user's file.
9. **Tests** `test/test_export_geotiff.cpp` (GTest, synthetic layers built in a temp dir with `saveTiles`, plus sidecar tiles hand-written or from `overview_builder` and a hand-written `coverage.json`):
   - selection: native-wins (native and sidecar at the same level, native values appear); mixed native+sidecar at one level (`SOURCE_KIND=mixed`, no silent NaN); native tiles at other levels in the box excluded with WARNING where they become holes (coarser native under an empty position; finer native over an empty sidecar position) or lie beneath a native ancestor; no hole or shadow counted for a finer native tile whose export-level position is outside the export (box edge just past a tile boundary); a coarser native tile under export-level tiles (native, then sidecar) with band-1 NaN cells inside the window warns with the NaN count, and not when the window covers only valid cells; no warning for a sidecar-covered coarse export or a coarser native tile under fully valid export-level tiles; finest-native-level judged inside the box; no-upsample refusal; coarse level absent from sidecar refusal; coarse level read from sidecar with geometric error from `coverage.json`; box outside coverage but inside a sidecar level; box intersecting nothing.
   - placement: asymmetric values across a 2x2 tile neighbourhood (E-W and N-S neighbours) with a box that snaps outward and clips partial tiles, checking pixel values at known positions (row flip, integer offsets); NaN holes between tiles plus NoData count (total - non-NaN).
   - refusals: polar box (|lat| >= 72) and scale-boundary box; corrupt/unreadable tile in the box; a tile with the right origin but the wrong pixel size or a rotation; a tile whose origin is a fraction of a cell off its grid; mixed band counts; non-float dtype (uint16); a finite or infinite no-data value; an output anywhere in the store (layer, sidecar, subdirectory, sibling layer, `registry.json`, through a symlinked layer or a symlinked output path; the registry of a layer nested below its usual depth; a sibling layer of a store whose other layer holds a stray `registry.json`; both stores when a symlinked layer's link lives in another store); an `overviews/` sidecar given as the layer (plain, trailing slash, through a symlink), while a layer with no registry anywhere still exports; each followed by a check that no output and no stray temporary file exists.
   - output handling: existing `-o` overwritten on success and untouched on refusal, and byte-identical after a failure that happens after the dataset was created (a truncated tile that passes the header probe and fails in `loadTile`), with no temporary file left; foreign `out.tif.tmp` / `out.tif.tmp.XXXXXX` lookalikes survive a refusal and a success; the output's mode follows the umask; a replaced output's stale `.aux.xml` statistics, `.ovr` overviews and `.msk` mask are removed while look-alike names survive; concurrent exports to one output all succeed and leave no temporary file; an `overviews/` swapped in by another thread while an export reads sidecar tiles fails it, leaving the existing output untouched.
   - datum: empty-datum WARN (depth, wording "source datum conversion not recorded", `VERTICAL_DATUM=WGS84_ELLIPSOIDAL`, `SOURCE_VERTICAL_DATUM=UNKNOWN`); non-empty datum recorded in `SOURCE_VERTICAL_DATUM`; absent registry warns, not refuses; trailing-slash `<layer_dir>`; symlinked `<layer_dir>` finds the real registry, not a decoy beside the link; no warning and `NOT_APPLICABLE` for 3-band backscatter.
   - values: 3-band Float32 path with band names; Float64 to Float32 cast values (NaN preserved).
   - cap: `max_pixels` equal to width*height accepted, one less refused; 64-bit overflow-sized box refused without allocating.
   - output read back with GDAL for size/geotransform/descriptions/metadata.
   - signal during the rename: a SIGHUP sent to the exporting thread the moment another thread sees the output's inode change is delivered only after the replacement is counted and the old `.aux.xml` removed (fails every run with the block removed); a refusal does not bump `exportOutputsReplaced()`.
   - CLI: the built executable is run by path for SIGINT and SIGTERM during a long write (dies of the signal, temporary file removed, existing output untouched), for SIGTERM once the output's inode has changed (never "nothing written"; a run that dies of it says the output WAS replaced), the usage exit code (box required), success summary + datum WARNING on stderr, refusal exit code, `--max-pixels`, and malformed numbers (signs, whitespace, non-digits) as usage errors.
10. **Real-data check (read-only)**: after implementation, run the CLI on the Appledore box against `~/data/world/imagery/backscatter/survey` at level 10, output to `.agent/scratchpad/`, and inspect with `gdalinfo -stats`. Never write to the host store.

## Principles Self-Check

| Principle | Consideration |
|---|---|
| Robustness on open water | Refusals are explicit (finer than native, missing sidecar level, empty box, over cap, polar/scale-boundary box, non-float dtype, mixed band counts, unreadable tile); no partial output file or stray temporary file |
| Fail loud, not silent | Output labelled ellipsoidal; missing source-datum record warns loudly and is recorded; excluded native levels warn; NoData count always reported |
| Generic over instance | Layer-agnostic; no layer name hard-coded; datum read generically |
| Local-first / read-only on data of record | Tool only reads the store; real-data check writes to scratchpad |
| Test with the fix | Full synthetic test matrix as above |

## ADR Compliance

| ADR | Triggered | How addressed |
|---|---|---|
| ADR-0011 overview contract | Yes | Reads flat `overviews/<level>_<row>_<col>.tif` and `coverage.json` only; per-tile precedence native then sidecar then hole at the requested level; sidecar is derived; tolerates a missing/rename-aside-gap `overviews/` by a clear refusal (not a cached "none"); no folding |
| ADR-0007 (A.2) | Yes | `survey` is canonical backscatter layer; directory is an explicit argument; no alias logic |
| ADR-0002 | Yes | Depth tile format (2 bands, Float64) read as-is; D4: stored depth is always WGS84 ellipsoidal, registry `datum` is the source datum and is recorded separately |
| ADR-0010 | Yes | Reads the world layout in place; no layout change |
| ADR-0013 D8 | Partially | Exporter is a consumer of the sidecar; native wins, derived never merged into native |

## Follow-ups (deferred, not implemented here)

- MBES backscatter overview builder (exists as uma#390); until then coarse backscatter exports are refused.
- Survey-explorer export action in marine_perception_tools (perception_tools#27 overlap).
- Optional `--datum-override` if the warning proves noisy.
- Explicit `--layer-kind` / `--band-names` overrides (dropped from Slice A as out of approved scope).
- Extra provenance tags (`HORIZONTAL_CRS_NOTE` re NAD83(2011) labelled WGS84, `SOURCE_LAYER_DIR`, `BOX`) if the operator wants them.
- Polar (|lat| >= 72) and scale-boundary boxes (needs per-band georeferencing or reprojection).
- `tile_io`'s `loadTile` validates only a tile's origin (to half a cell), not its pixel size or rotation (pre-existing). The exporter's probe checks the pixel grid and the exact origin for its own reads; tightening `loadTile` itself, for every reader, is a separate change to `tile_io`.
